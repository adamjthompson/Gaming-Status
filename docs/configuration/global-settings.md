# Global Settings
These variables control how the integration handles platforms, caching, and network drops across all players.

* **Enabled Platforms:** Select which gaming platforms to track (Steam, Xbox, PlayStation, Discord, Playnite, Gaming Status Agent, and Custom).
* **Enable PS3 Tracking:** Adds the PS3 Media Player field (see [Manage Players](manage-players.md)) to PlayStation-enabled player profiles.
* **Cache Settings:** Toggle local image caching (default: on), automatic vibrant color extraction (default: on), and configure background cleanup limits (Max Files, default 200 & Max Days, default 30).
    * With caching *enabled*, artwork is downloaded to your Home Assistant storage, making dashboard loads instant, allowing offline artwork access, and preventing broken images during internet outages. *If you use Discord notifications but do NOT have an external Home Assistant URL, image attachments will fail.*
    * With caching *disabled*, artwork is pulled directly from SteamGridDB (raw web URLs) each time a game is loaded. *If you have an external Home Assistant URL, it is recommended that you enable caching.*
* **Grace Periods (Network / Away / Transition):** Configure exactly how long the integration waits during network drops, idle statuses, or game switches before ending a session. Defaults: 300 / 600 / 120 seconds.
    * **Offline (Network) grace period:** Handles total connection loss, e.g. a PlayStation losing WiFi mid-game or the Steam API temporarily going down. The player keeps showing as "Playing" and playtime keeps counting for the grace period. If they reconnect before it ends, it's as if nothing happened; if it runs out, those seconds are retroactively subtracted from their daily total and they're marked "Offline". *This also factors into how long it takes to notify you that a session has ended.*
    * **Away grace period:** How long to wait before a Steam "Away" status becomes "Offline", preventing artificially long sessions when a game is left open but not played.
    * **Game transition grace period:** Handles game switching while the player stays online, e.g. closing Helldivers 2 and opening Marvel Rivals, or a crash to desktop followed by an immediate relaunch. Instead of ending the session and starting a new one seconds later, the timeline is stitched together so quick swaps or crash reboots don't fracture session history into tiny pieces.
* **Minimum Session Duration:** Prevents quickly opening and closing a game (like launching a launcher) from cluttering your play history. Shorter sessions are discarded from history, don't count toward playtime totals, and won't display on the dashboard. Default: 300 seconds.
* **Master Handoff Grace Period:** If a player is genuinely, continuously active on two platforms at once (e.g. playing a Steam game while also idling into a console game), whichever platform is currently shown on the Master sensor keeps that spot indefinitely as long as it stays healthy — this setting only comes into play once that platform's *own* connection drops into its own offline-grace or ghosted state and stays stuck there continuously; only after it's been stuck for this long does a more-recently-started game on another platform get to take over the display. Prevents notification spam from a platform's brief connectivity blips repeatedly flipping which one is shown. Default: 300 seconds (5 min). Set to 0 to restore instant hand-off.
* **Session Start Confirmation:** How long a newly detected game must still be reported before a session actually starts. Useful when a sensor is unreliable and briefly reports games that were never launched — without this, a flicker lasting a second creates a real session, fires a "started playing" notification, and (because the offline grace period then holds it) can even record play time. Genuine sessions are simply delayed by this long, and their start time is backdated so no play time is lost. Does not apply to Discord, which is event-driven and has nothing to re-check. Repeated flickers can otherwise chain into a session long enough to be recorded. Leave it at 0 if your sensors are well behaved. Default: 0 (off). A good starting point if you need it is 15-30 seconds.
* **Reset History:** A toggle to clear all accumulated daily/weekly/all-time playtime and session history (including the recent sessions log), for every player, upon the next Home Assistant restart. Applies once, then automatically switches itself back off. Doesn't touch achievement/trophy history — use a player's own **Clear achievement/trophy history** option for that. *Use with caution!*
* **Remove Disabled Sensors:** Automatically deletes orphaned sensors from the registry if their platform is un-checked from the Enabled Platforms list.
